# Entity Relationship Diagram（ER図）

データベース設計におけるエンティティ（テーブル）間の関係を表現する図です。

## 基本構文

```mermaid
erDiagram
    CUSTOMER ||--o{ ORDER : places
    ORDER ||--|{ LINE_ITEM : contains
    PRODUCT ||--o{ LINE_ITEM : "ordered in"
```

## カーディナリティ（多重度）

```mermaid
erDiagram
    A ||--|| B : "1対1"
    C ||--o{ D : "1対多（0以上）"
    E ||--|{ F : "1対多（1以上）"
    G }o--o{ H : "多対多"
```

### カーディナリティ記号一覧

| 左側 | 右側 | 意味 |
|------|------|------|
| `\|o` | `o\|` | 0または1 |
| `\|\|` | `\|\|` | 必ず1 |
| `}o` | `o{` | 0以上（多） |
| `}\|` | `\|{` | 1以上（多） |

## 属性の定義

```mermaid
erDiagram
    USER {
        int id PK
        string email UK
        string password_hash
        string first_name
        string last_name
        datetime created_at
        datetime updated_at
    }
```

## 属性の型と制約

```mermaid
erDiagram
    PRODUCT {
        int id PK "主キー"
        string sku UK "一意制約"
        string name "商品名"
        text description "商品説明"
        decimal price "価格"
        int stock_quantity "在庫数"
        int category_id FK "カテゴリID"
        boolean is_active "有効フラグ"
        datetime created_at "作成日時"
    }
```

### 制約キーワード

| キーワード | 意味 |
|------------|------|
| `PK` | Primary Key（主キー） |
| `FK` | Foreign Key（外部キー） |
| `UK` | Unique Key（一意キー） |

## リレーションシップラベル

```mermaid
erDiagram
    AUTHOR ||--o{ BOOK : writes
    PUBLISHER ||--o{ BOOK : publishes
    BOOK }o--o{ CATEGORY : "belongs to"
    CUSTOMER ||--o{ REVIEW : "writes"
    BOOK ||--o{ REVIEW : "has"
```

## 自己参照リレーション

```mermaid
erDiagram
    EMPLOYEE ||--o{ EMPLOYEE : manages
    CATEGORY ||--o{ CATEGORY : "parent of"
    COMMENT ||--o{ COMMENT : "reply to"

    EMPLOYEE {
        int id PK
        string name
        int manager_id FK
    }

    CATEGORY {
        int id PK
        string name
        int parent_id FK
    }

    COMMENT {
        int id PK
        text content
        int parent_id FK
    }
```

## 多対多の中間テーブル

```mermaid
erDiagram
    STUDENT }o--o{ COURSE : enrolls
    STUDENT ||--o{ ENROLLMENT : has
    COURSE ||--o{ ENROLLMENT : has

    STUDENT {
        int id PK
        string name
        string email UK
    }

    COURSE {
        int id PK
        string code UK
        string title
        int credits
    }

    ENROLLMENT {
        int id PK
        int student_id FK
        int course_id FK
        string grade
        datetime enrolled_at
    }
```
